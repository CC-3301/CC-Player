# ADR-0047 字幕字体以内嵌中文字体兜底

状态：已接受

## 背景

字幕由 libmpv 的 libass 渲染，字体经 fontconfig 在系统字体目录里查找。ASS 文件按样式指定字体名（常见为微软雅黑一类桌面字体），设备上不存在时 fontconfig 会按字形逐个回退，中文从一款字体出、省略号与破折号从另一款西文字体出，于是符号的宽度与基线不对，看起来「不是正常的」。

## 决策

- APK 内嵌一款中文字体的子集：GB2312 常用字表加**全部中文标点**，不裁剪标点。体积上限 5MB。
- 启动时把字体从 assets 释放到应用私有目录，作为 mpv 的字幕字体目录下发。
- 随字体提供一份 fontconfig 配置：把 sans-serif、serif 的默认族指向内嵌字体，未命中的族一律落到 sans-serif。片源里指定的任何字体名都不做逐条映射。
- 不使用强制覆盖样式：ASS 的排版、定位与描边按文件自身样式渲染，只替换字体来源。
- 诊断开关打开时把 libmpv 的日志级别放到 warn，便于确认字体缺失告警；关闭时维持 error。

## 后果

- 省略号、破折号、间隔号等中文标点与汉字出自同一字体，宽度与基线一致。
- 生僻字可能缺字：子集只覆盖 GB2312 常用字，超出范围的字仍走系统字体回退。
- APK 体积增加约 3–5MB。
- 片源为艺术字或特殊字重时，字形会被内嵌字体取代，与原设计不完全一致。

## 依据

现状是应用侧零字体配置：初始化只下发 13 个选项，无任何 sub-* 项，也没有字体目录或内嵌字体。libass 的字体缺失告警为 warn 级，当前日志级别下不可见。
