# ADR-0042 播放页收一个会话事实与一个动作接口

状态：已接受

## 背景

播放页是应用里最大的一屏：画面、控制层、进度、字幕、睡眠定时、播放列表抽屉都在这里。现在它要靠一长串参数才画得出来，参数由界面层一项项收上来再转手。

同一件事也被算了不止一遍。「现在算不算在加载」由四个布尔拼出来，界面层和播放页各拼一次；四个布尔能拼出的组合大多不成立，能成立的只有几种。结果是加一个显示项要连着改好几处，改错一处就是提示残留或按钮该灰没灰。

## 决策

- 播放页只收两样：一个会话事实 `PlayerScreenState`，一个动作接口 `PlayerActions`。
- 会话事实内部分三组：播放进度、加载阶段、菜单偏好。
- 加载阶段收成一个枚举：准备中、等待接手、加载中、切集中、恢复中、就绪。界面只判这一个值，不再用多个布尔自行组合。
- 界面层不再自行收集播放控制层的 Flow：播放页 ViewModel 负责收集、派生与组装这套事实。
- 事实按值传，不引入 `State<T>`；列表、文件与回调不放进事实对象，避免整个对象被判不稳定而每次重组都重画。
- 列表、文件与回调由播放页另行接收：内容（列表与文件）一个参数，接入口（宿主与平台回调）一个参数。`PlayerActions` 只放用户动作。
- 动作接口每个动作一个方法，不引入意图对象。
- 事实对象只在播放页边界构造，界面层不再逐项转手。

## 后果

- 加一个显示项只改一组事实与它自己的使用处，不再多处接力。
- 不成立的加载组合写不出来，界面里重复的「动作是否允许」判断随之消失。
- 代价：新增一个 ViewModel，接管现在界面层的收集与派生；它比播放页活得久：离开播放页不停收集，清理点在播放会话结束（关闭播放页或服务断开）。
- 代价：本次不拆子组件，重组范围仍是整屏。播放页若出现掉帧，下一步是把三组事实分别下传、按需读取，而不是继续加参数。
