# ADR-0034 视频画面改用常驻 Surface

状态：已接受

## 背景

退到后台时系统会回收 SurfaceView 的 Surface。播放核心用的是窗口句柄方式，换窗口必须卸载并重建整条视频输出，这一步同步阻塞核心线程约 0.3–0.5 秒，之后还要重建输出并精确重解码，合计 1 秒以上；音频由核心线程喂给输出队列，队列只装 0.2–0.5 秒，耗尽即欠载，用户听到断音。

调大音频缓冲只能提高容忍度，且官方标注该参数仅供测试；沿用窗口句柄方式时，取消重建、切换视频轨、离屏窗口顶替这几条路都试过，均会改窗口或触发重建。

## 决策

- **画面载体改为 TextureView**：视频画面渲染到 TextureView 的 Surface。该 Surface 由应用进程持有，窗口不可见时不销毁，因此退到后台不再更换窗口句柄。
- **退后台不重建视频输出**：后台只停止画面呈现，不卸载视频输出、不改窗口句柄；回前台继续用同一个 Surface。
- **离开播放页不重建视频输出**：返回浏览界面且继续播放时，播放页视图常驻、只隐藏且不接收触摸，Surface 不销毁；同时关闭视频轨、只保留音频，回播放页重新选回视频轨并复用同一 Surface。判据是离开播放页期间听不出音频中断，日志不出现拆视频输出记录。
- **音频不断**：退后台路径不产生任何音频命令；判据是听不出中断、爆音、重音。
- **代价与边界**：画面多一次 GPU 合成，功耗高于叠加层；不支持 DRM/secure 视频；HDR 不能直通。以上为已知限制，不做绕行。
- **回前台画面规则不变**：播放态回前台撤旧画面、纯黑等新帧；暂停态保留最后一帧并做位置中性刷新。

## 后果

- 退后台不再触发视频输出重建，音频不再因重建欠载。
- 后台无人消费画面时的反压行为需要验证：缓冲区满时视频输出线程可能阻塞，若反压到核心线程则仍可能出现卡顿，需真机确认。
- 4K 高码率视频的合成开销需真机确认是否掉帧。

## 依据

mpv 窗口句柄方式在窗口变化时必然重建视频输出；渲染目标归调用方的渲染接口未在当前产物中暴露。上游同类应用在窗口句柄方式下也无法避免重建。实测：拆视频输出 297–448ms、重建 112–220ms、重新出声 294–391ms。
