# ADR-0040 字节源归还按保留集合判定

状态：已接受

## 背景

播放一个网络视频时，应用要知道「这条读连接现在还有没有人用」。不用了就该还掉：不还，句柄越攒越多，服务器那头也一直被占着。

判据本身只有一句：当前目标是否仍被读取。ADR-0039 已经这么写了。但这句话在代码里没有落脚点，凡是可能「不用了」的地方都各写一遍条件——暂停在片尾、换到别的目标、连点下一集、停止、播完、离开播放页。条件都不算错，只是同一件事写了多遍，改一次要在多处按同样的方式改，漏一处就漏一条连接。

## 决策

- 判据收成一处：播放控制层派生「此刻仍需保留的媒体位置集合」。
- 接缝只加一个方法 `NetworkStreams.retain(locations: Set<String>)`：声明保留哪些位置；不在集合里的已就绪字节源由回环条目当场摘走，在关源线程关闭。地址保留，下一次请求重新建立。
- 差集与按协议分派在路由层完成：路由层记住上一版集合，只处理被移出集合的位置。播放控制层仍只通过一个注入的出口调用，不认识 `NetworkStreams`。
- 只在被显式调用时动作：引擎回声（迟到的暂停、结束回调）不触发归还。
- 幂等：集合未变化时不动作。同一位置的不同列表项是同一条源，从一个换到另一个不算移出。
- 归还不抢先于新目标下发：连点前移时，旧目标在新加载下发之后才归还。顺序由调用方保证，不由状态重算推出。
- 范围只含归还。陈旧标记仍由回环条目持有；退到后台的丢弃仍由 `StaleSourceDiscardPolicy` 判定。
- ADR-0039 的所有权分配不变：字节源只由回环条目持有与关闭，创建与关闭只在 IO 线程。

## 后果

- 新增一种「不再读取」的时机，只改判据所在的那一处；传输层与界面都不必跟着改。
- 接口多一个方法，SMB、WebDAV 与测试用内存源各实现一次转发。
- 调用点数量不变：各处仍显式声明一次。收敛调用点是另一件事，不在本决策内。
- 「当前目标仍被读取」的例外（离开播放页但仍在后台播放、暂停在片尾）只在一处表达，不再由各调用点各自记住。
