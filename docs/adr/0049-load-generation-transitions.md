# ADR-0049 加载代际统一承载代际内迁移

状态：已接受

## 背景

旧片播放中打开另一个目标时，控制层要建立新代际的目标、令牌、出声归属、屏上画面与就绪证据。首次打开、切集与重发目前分别组装这些字段，测试也可以绕过真实加载路径直接摆字段。

加载代际虽然是唯一事实持有者，调用方仍必须知道每种加载的字段级迁移，可能写出类型允许但业务不允许的组合。

## 决策

- 加载代际统一承载首次、打开、切集、恢复原片、改目标、重发、媒体加载完成与目标就绪的代际内迁移。
- 收拢范围仅限目标、引擎令牌、出声归属、屏上画面与就绪证据的原子变化；这些事实不再由调用方逐字段组装。
- 播放控制层继续负责播放列表、进度、字幕、引擎命令与加载看护调度，不把整个播放会话并入加载代际。
- 打开交接继续独立持有入口阶段、代际分配、兜底计时、待起播与起播握手，遵循 ADR-0041；本决策不合并这两个 module。
- 代际测试驱动真实迁移，不手工摆字段冒充首次打开或切集。加载看护、首帧、位置前进、重发与恢复规则不变。

## 后果

- 每种加载路径复用同一组代际不变量，新增路径不再复制字段清单。
- 播放控制层测试聚焦引擎命令、进度、字幕与看护副作用；代际测试聚焦事实迁移。
- 加载代际保留纯 JVM 测试 seam，删除它仍会把复杂度倒灌回播放控制层。
- 本决策不改变打开、切集、恢复与重发的用户可见行为。
