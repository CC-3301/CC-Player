# ADR-0043 条目抽帧状态收成一份

状态：已接受

## 背景

列表里每个视频要一张封面。取不到的时候，应用得记住三件事：这个试过了先别急、这个确认没图过一会儿再说、这个已经失败过几次。

这些记忆现在分成好几份：一份记本地失败了几次，一份记界面上重试了几次，一份记确认无图，一份记预取别再试，一份记时长读取失败后多久再补。各份的寿命、容量上限和淘汰方式都不一样。

结果是同一个条目在不同地方被记成不同状态。用户滑走再滑回来，重试机会会莫名少一次；某份记录满了会被整体清空，已经放弃的条目又从零开始试。

## 决策

- 一个条目一份状态：上次结果（出图 / 无图 / 失败及其阶段）、已试次数、最早可再试时刻、是否对预取抑制。
- 这条记录由抽帧源持有；原先分散的几份并进来，不再各记一份。
- 重试节奏从状态读：抽帧源与界面调度层读同一份「已试几次、何时可再试」，不再各自计数。上限取值按 ADR-0027（本地与网络同一规则：首发 1 次加重试 3 次，间隔 1 秒、3 秒、9 秒）。
- 正在进行的活不进状态：同一个键的并发合并与后台补读时长任务仍由抽帧源单独管理，状态只描述结果。
- 淘汰统一为一种：容量上限加可选过期，各记录的差异只体现在参数上。
- 一次失败的最多尝试次数、重试间隔与重新订阅后的配额按 ADR-0027 取值，本决策不改数值。
- 记录满时按最久未用逐条淘汰，不整体清空。

## 后果

- 「这个封面现在什么状态」只有一个地方可查，重试节奏的改动只动一处。
- 记录满时按最久未用逐条淘汰，放弃过的条目不会突然从零再试，由测试钉住。
- 代价：状态字段比单张表多，本地与网络两种上限要在同一份状态里区分来源。
- 代价：迁移时既有计数必须搬过去，否则会多出几次重试。
