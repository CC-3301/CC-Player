# ADR-0036 播放页加载期控件可用性

状态：已接受

## 背景

播放核心在首次打开、切集、恢复原片这三种加载期间，界面把所有控件统一判为不可用，点击被静默丢弃，只把图标调淡。用户看到的是“按了没反应”，而且点得越早越容易落进这个窗口——加载耗时实测 1.7~2.8 秒，这段时间足够点三四次。

但被拦的控件不是一类东西。“更多”面板里没有任何一项依赖加载完成；音量走系统媒体音量；“锁定”只改界面状态。真正与加载冲突的是会改写“加载哪个媒体”或“起播时是否暂停”的控件，以及在这一窗口内按下必然无效的控件。

同一层还有两处独立缺陷：进出播放页时主线程同步等待视频输出挂载（上限 2 秒），期间所有点击延迟；首次打开期间界面沿用上一会话状态，缓冲圈不出现，屏幕纯黑。

## 决策

- **拦截判据**：只有在加载期间会改写加载目标、会改写起播暂停意图，或按下必然无效的控件才拦截；其余控件照常可点。
- **拦截清单**：播放/暂停、上一集、下一集、旋转、进度条、播放列表。
  - 播放/暂停与上一集/下一集改写加载目标或起播暂停意图。
  - 旋转在当前视频比例未知前会先锁住方向，按下看不到变化。
  - 进度条在切集期间显示的是上一集的时长与位置，拖动会改写本次加载的起播位置。
  - 播放列表抽屉内的条目会改写加载目标，与其让抽屉能开、条目点了没反应，不如整块拦截。
- **放行清单**：更多、字幕、音量、锁定。
- **禁用外观只用于仍被拦截的控件**：可点的控件不得显示为禁用外观，避免“看着能点、点了没反应”。
- **首次打开显示缓冲圈**：加载期间显示居中转圈，不显示任何文字提示，直到首个画面出现或加载失败。
- **主线程不等待**：进出播放页时不得在调用线程上同步等待视频输出就绪。

## 后果

- 加载期的“更多”不再无效；面板里切换“解码”会重建解码器并可能推迟首帧，属已知代价，不做额外规避。
- 加载期仍可点“锁定”，锁定时面板自动关闭。
- 字幕按钮在加载期可开，面板内的轨道选项另有判据：切集开始时轨道列表已清空，面板呈现空列表。
- 主线程不再被阻塞，进出播放页后所有控件恢复即时响应。
- 缓冲圈只在准备阶段出现，不代表连接进度；连接层失败仍按既有文案提示。

## 备选

- **全放开**：否决。改写加载目标的控件与在途加载会互相打架，此前出现过“新片加载指令被吞、十秒后判失败”的事故。
- **全部保留**：否决。用户感知为控件损坏，且“更多”等控件与加载无因果关系。
- **加防抖或忽略关闭窗口**：否决。没有证据指向连点，属补丁式修改。
- **排队执行**：否决。排队只是把“点了没反应”换成“点了过一会儿才动”，不解决判断错误。
