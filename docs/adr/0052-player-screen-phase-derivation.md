# ADR-0052 播放页阶段统一覆盖缓冲与返回决策

状态：已接受

## 背景

打开交接已接手但目标尚未首个就绪时，随后可能进入切集或恢复原片。播放页阶段、入口缓冲与返回决策目前分别解释同一组控制层事实，恢复与切集的优先级也随之重复。

控件可用性已经消费播放页阶段，返回决策却仍要求调用方另算准备期与加载中，ADR-0042 的单一阶段事实尚未收净。

## 决策

- 播放页会话派生统一提供播放页阶段与缓冲事实，界面显示、控件可用性与返回决策不再各自组合多个加载布尔。
- 返回决策消费统一阶段，只另加失败、片尾与 APP 内后台播放等独立事实。
- 打开交接继续只持有入口阶段、代际、兜底计时、待起播与起播握手，不承担播放页显示派生；ADR-0041 的 module 职责不变。
- 播放页继续接收一个会话事实与一个动作接口，动作仍每个用户动作一个方法，不引入意图对象。
- 实施前必须用现有场景证明等价，尤其覆盖控制层缓冲，以及已接手状态保留到下次打开的规则；不得把现有判断机械替换成一次枚举比较。
- 准备期、恢复优先于切集、加载期控件与缓冲提示的用户可见规则不变。

## 后果

- 阶段优先级只维护一份，显示、置灰与返回使用同一事实。
- 打开交接测试回到交接本身，不再复制控制层状态矩阵。
- 播放页会话场景可以统一覆盖缓冲、控件可用性与返回决策。
- 本决策落实并补足 ADR-0042，不改变 ADR-0024、ADR-0036、ADR-0038 的行为口径。
