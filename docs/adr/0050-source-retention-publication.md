# ADR-0050 保留集合发布并入显式播放意图收尾

状态：已接受

## 背景

用户连点下一集时，旧目标必须在新加载下发后再移出保留集合；耳机拔出、定时暂停与片尾停止则要及时归还。保留集合的计算已经收口，但发布时机仍由各播放分支分别调用，漏掉一个分支就会多留字节源与网络源会话引用。

这里需要收拢的是显式播放意图的收尾，不是再增加一层只转发事件的 module。

## 决策

- 在播放控制层内，显式播放意图的状态迁移与保留集合发布在同一处收尾；普通意图不再分别补发布调用。
- 切集保留特殊顺序：新加载下发之后才发布保留集合。
- 不监听状态流自动发布，也不由引擎回声触发归还；发布仍只来自显式播放意图。
- 保留集合仍按“当前目标是否仍被读取”派生，路由差集、回环条目摘走与后台关闭的 implementation 不变。
- 不新增只转发播放事件的 shallow module，也不把 SMB/WebDAV adapter 的差异并入播放控制层。
- 测试继续通过公开播放动作、引擎替身与注入的保留出口验证，不暴露保留集合或回环条目的内部观察孔。

## 后果

- 新增一种“不再读取”的显式意图时，状态变化与发布时机可在同一处审查。
- 现有保留集合、协议路由与回环归还链全部复用。
- 字节源仍只由回环条目持有与关闭，继续遵循 ADR-0039、ADR-0040。
- 本决策不改变播放、暂停、切集与后台播放的用户可见行为。
