# ADR-0032 封面体系

状态：已接受

## 背景

封面在三处出问题：纯音频点开后先黑一段才出图；部分内嵌封面的音频文件永远取不到；视频封面偶发缺失，且缺失后不会自己补回来。

根因分布在三条独立链路上：播放页没有图片层，封面只能等播放核心把内嵌图当视频帧画出来；系统取内嵌封面只走一条保守实现，标签过大或首张图异常就整体放弃；抽帧失败与重试策略把失败当成终态。

## 决策

- **播放页封面层**：进入播放页的目标是纯音频时，立即显示该目标已缓存的封面图；播放核心把封面帧上屏后隐藏该层。视频目标不使用封面层。没有可用封面时显示占位图。
- **封面来源**：列表缩略图与播放页封面层共用同一份缓存，不各自解码。
- **内嵌封面两条路**：先走系统取内嵌封面；取不到或系统图解码失败时，用自实现的 ID3v2 APIC 解析再取一次，只解封面帧，不做完整标签解析，不引入第三方标签库。标签可读但没有封面帧才算无图；读取失败、系统图解码失败按抽取失败记录阶段。
- **视频封面只来自抽帧**：Matroska 容器不含封面图，不做容器附件解析。
- **失败分阶段记录**：抽帧失败必须区分阶段——打开数据源、读取、解码、超时；日志按阶段各写一类，便于判断卡在哪一环。
- **失败不是终态**：
  - 本地与网络同一规则：按 1 秒、3 秒、9 秒递进重试，单个最多 3 次（首发 1 次 + 重试 3 次），用尽后显示占位图；
  - 次数用尽后，回到前台、重新进入可见范围、下次冷启动都重新给一轮；失败不记为永久无图；
  - 「确认无图」的进程内记忆带过期时间（10 分钟），过期后可再取；
  - 抽取失败不写「无图」缓存，只有解码成功但没有图才写。
- **会话作废后的补取**：SMB 会话作废导致抽帧失败时，该条目不算终态；条目重新订阅时重新抽取，下一次抽取重新建连。
- **诊断**：封面失败、取消、超时、无图各有一条日志，跟随诊断开关。
- **视频封面改用 Media3 抽帧**：视频封面不再走系统取帧接口与自建随机读拼接。本地与网络共用 Media3 的 `FrameExtractor`（`media3-inspector-frame`），封装解析与解码由组件负责；网络数据源把现有 SMB/WebDAV 随机读句柄包装成 Media3 `DataSource`，复用已有预读，不另写一套读取。抽帧实例只在主线程访问，网络字节由 Media3 的加载线程读取。
- **保留选点与不合格剔除**：本地按比例取 2 个候选；网络取 `min(max(1% 时长, 1 秒), 30 秒)` 主候选，不合格时再退 60 秒，最多 2 个候选。纯色与近黑（采样亮度平均值低于阈值）都不算可用封面；候选都解码出来仍不合格时直接使用已解出的那一帧，不再追加候选。
- **两段等待有上限与日志**：网络抽帧的打开数据源与等解码许可两段各自有可取消的等待上限，并各写一条等待耗时日志；本地抽帧不单列打开段，打开与解码由整次抽帧上限覆盖。开始抽帧与完成耗时各有一条日志。
- **取消不是终态**：可见请求被取消后保留订阅，条目再次进入可见范围时重新入队；取消原因（离屏 / 列表重建 / 换源 / 订阅取消）写一条日志。

## 后果

- 纯音频点开后不再有黑屏空窗，封面在进入播放页时即可见。
- 内嵌封面覆盖范围扩大，但自实现解析需要处理标签编码与长度边界。
- 封面重试会增加后台抽取次数；重试低于可见条目的优先级，不挤占可见封面。
- Media3 抽帧依赖增加安装包体（约 2 MB）；抽帧任务由组件内部串行执行，外部再以全局许可约束，慢源不会无限期占住队列。

## 依据

AOSP `ID3.cpp` / `MP3Extractor.cpp`（标签上限、首张 APIC 失败即放弃）；mpv `--audio-display` 语义（内嵌图作为视频轨渲染）；Media3 `FrameExtractor` 的共享播放器与任务串行语义；ADR-0017、ADR-0021、ADR-0027。
