# ADR-0032 封面体系

状态：已接受

## 背景

封面在三处出问题：纯音频点开后先黑一段才出图；部分内嵌封面的音频文件永远取不到；视频封面偶发缺失，且缺失后不会自己补回来。

根因分布在三条独立链路上：播放页没有图片层，封面只能等播放核心把内嵌图当视频帧画出来；系统取内嵌封面只走一条保守实现，标签过大或首张图异常就整体放弃；抽帧失败与重试策略把失败当成终态。

## 决策

- **播放页封面层**：进入播放页的目标是纯音频时，立即显示该目标已缓存的封面图；播放核心把封面帧上屏后隐藏该层。视频目标不使用封面层。没有可用封面时显示占位图。
- **封面来源**：列表缩略图与播放页封面层共用同一份缓存，不各自解码。
- **内嵌封面两条路**：先走系统取内嵌封面；取不到时用自实现的 ID3v2 APIC 解析再取一次，只解封面帧，不做完整标签解析，不引入第三方标签库。两条都失败按无封面处理。
- **视频封面只来自抽帧**：Matroska 容器不含封面图，不做容器附件解析。
- **失败分阶段记录**：抽帧失败必须区分阶段——打开数据源、读取、解码、超时；日志按阶段各写一类，便于判断卡在哪一环。
- **失败不是终态**：
  - 本地抽取失败纳入有限重试，最多 3 次，仍失败显示占位图；
  - 网络抽取按现有递进重试，次数用尽后条目再次进入可见范围时重新给一轮；
  - 「确认无图」的进程内记忆带过期时间（10 分钟），过期后可再取；
  - 抽取失败不写「无图」缓存，只有解码成功但没有图才写。
- **会话作废后的补取**：SMB 会话作废导致抽帧失败时，该条目不算终态；下一次进入可见范围或下一次会话重建后重新抽取。
- **诊断**：封面失败、取消、超时、无图各有一条日志，跟随诊断开关。

## 后果

- 纯音频点开后不再有黑屏空窗，封面在进入播放页时即可见。
- 内嵌封面覆盖范围扩大，但自实现解析需要处理标签编码与长度边界。
- 封面重试会增加后台抽取次数；重试低于可见条目的优先级，不挤占可见封面。

## 依据

AOSP `ID3.cpp` / `MP3Extractor.cpp`（标签上限、首张 APIC 失败即放弃）；mpv `--audio-display` 语义（内嵌图作为视频轨渲染）；ADR-0017、ADR-0021、ADR-0027。
