# ADR-0044 抽帧准入保持两条独立机制

状态：已接受

## 背景

取一张封面要占住两样有容量上限的东西：解码许可只有 1 个；预读线程只有 1 条。两者都按列表索引（rank）排队，看起来像同一条队列的两种资源，很容易被合并成一条准入队列。

合并能少一处调度代码，但两处的排队语义并不相同：它们各自有不同的容量、不同的取消条件、不同的重试位置。合并后只要有一处的取舍变了，另一处也得跟着变。

## 决策

- 两者保持独立，不合并成一条准入队列；只共享 rank 数值这一个排队口径。
- 打开数据源不设名额：打开是毫秒级动作，名额只会把等待时间堆到解码之前。
- 整屏同轮入队保持两道让出：可见请求调度器与抽帧源各让出一次，使同一轮的请求在同一次调度里全部入队。
- 预取保留 120ms 启动延迟；预取不得占住唯一的解码许可。

## 后果

- 少一道让出会让同轮入队被切成两轮，出图顺序随之翻转，表现为后入队的那一行先出图。
- 删掉预取延迟会让预取先占住解码许可，可见项的封面排在它后面。
- 代价：两处调度各自维护容量与取消，改其中一处时要同时确认另一处仍成立。
