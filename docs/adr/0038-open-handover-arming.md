# ADR-0038 打开交接的接手兜底与迟到结果丢弃

状态：已接受

## 背景

从浏览界面打开一个目标时，应用先把它交给播放控制层，再等服务绑定与画面载体就绪才能真正下发加载。这条链上有三个已知风险：

1. **迟到结果**：入口准备是阻塞调用，取消只取消协程，异常仍会抛出并被捕获。若此时用户已经离开或已打开另一个目标，旧准备的成功与失败照样会收尾，表现为把正在看的播放页关掉，或起播一个已经被放弃的目标。
2. **一直不接手**：准备完成后，若系统服务或画面载体迟迟不就绪，页面会停在“只允许返回 + 转圈”的准备态，没有任何出口。
3. **误判**：如果兜底用墙钟计时，退到后台、锁屏、服务绑定慢都会把正常打开判成失败，撤回时还会把旧片的声音在后台恢复。

## 决策

- **入口阶段状态机**：入口只维护一个阶段值——准备中、等待接手、已接手、失败、已取消。同一时刻只有其中一个，界面显隐、兜底计时与收尾决策都从它推导，不再用多个布尔分别表达同一事实。
- **迟到结果丢弃**：入口准备的成功与失败都先判「是否仍是当前这次打开」，不是则一律丢弃，不得起播、不得离开播放页。判定依据是代际号与当前请求身份。
- **接手兜底**：准备完成、请求已可下发，但播放控制层在规定时间内仍未接手时，中止本次打开并回滚。
- **兜底只在等待接手阶段计时**：该阶段才代表「已准备好、但还没交给播放控制层」；其余阶段不计时。计时只在前台累计，退到后台、画面载体与系统服务尚未就绪期间不计时。
- **代际由入口分配、播放控制层沿用**：上报必须带同一代际才被接受，判定用严格相等，不比较大小；播放控制层不再自行发布第二份代际序列。
- **收尾按现有会话决定**：有旧会话时撤回打开交接、旧会话恢复出声与画面；无旧会话时退出播放页。
- **目标找不到时不得静默离开**：打开的目标不在列表里属于内部不一致，按失败路径收尾并给出既有失败提示，不静默返回。

## 后果

- 离开或改主意后，旧准备不会再影响当前播放页。
- 准备态有出口，不会永久停在转圈。
- 前台计时意味着用户反复前后台切换时兜底会被拉长，属可接受代价。
- 片尾停留的旧会话按普通退出处理，不撤回（见 ADR-0024 的返回规则）。
