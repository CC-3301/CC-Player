# ADR-0013 屏幕方向

状态：已接受

## 背景

播放页的方向要跟着设备转，又要区分“四向全跟、只跟横屏、只跟竖屏、跟视频比例”。自己听方向传感器意味着还要自己处理角度换算、换向迟滞、平放时角度不可靠、回前台重新判定——这些都是系统旋转逻辑已经在做的事。

## 决策

设置四选一：`屏幕方向（默认） / 横屏 / 竖屏 / 跟随视频`。

- **方向交给系统的传感器旋转模式**，App 不监听方向传感器、不算角度、不做迟滞与去抖：
  - **屏幕方向（默认）**：`SCREEN_ORIENTATION_FULL_SENSOR`，四向全跟。
  - **横屏**：`SCREEN_ORIENTATION_SENSOR_LANDSCAPE`，只在横屏族内跟传感器的正反向，物理转 90° 不跨族；反向是否生效见下条。
  - **竖屏**：`SCREEN_ORIENTATION_SENSOR_PORTRAIT`，只在竖屏族内跟传感器的正反向；反向是否生效见下条。
  - **跟随视频**：先按视频宽高比定族（≥1 横屏，<1 竖屏），再取对应族的 sensor 模式。
- 这四种模式不受系统“自动旋转”开关影响；设备接近水平时由系统忽略该角度，屏幕保持当前方向；180° 反向是否生效由系统的 `allowAllRotations` 决定，App 不保证。
- **只在五个时机下发方向**：进入播放页、方向设置变化、点转屏按钮、屏上画面比例变化、离开播放页。回前台、Surface 重挂、加载完成都不重新下发——回到前台不再先翻一次；目标相同不重复下发，切集后目标变化（如视频与纯音频互切）按档位重算一次。
- **方向等待**：「跟随视频」在视频比例未知期间不下发档位模式，锁住当前方向（`SCREEN_ORIENTATION_LOCKED`），不让屏幕跟着系统自动旋转转；比例到达后按它下发一次。没有视频方向的条目（音频扩展名或容器无视频轨）按「屏幕方向」处理，不等待。容器里有没有视频轨要加载完成才知道：加载完成算目标事实变化，允许按档位重算一次；在此之前按有视频轨处理，进入方向等待。
- **转屏按钮**：切换本次播放的覆盖方向（横 ↔ 竖），不改设置里的档位，离开播放页失效；覆盖优先于档位与宽高比。
- **离开播放页**：方向交回系统（`SCREEN_ORIENTATION_UNSPECIFIED`）。
- 画面由 mpv 按比例居中，黑边由 mpv 绘制。
- 播放页标题栏：横竖屏都有，背景透明；左侧依次为返回按钮与文件名，右侧为转屏按钮与更多按钮；叠加在画面上，不占布局高度；锁定态下只显示解锁按钮。
