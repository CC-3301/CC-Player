# ADR-0039 网络源字节源的所有权与重试分层

状态：已接受

## 背景

网络文件的读路径上原本有三套各自算账的机制：应用级 SMB 会话层按引用计数决定开与关、回环代理按条目缓存字节源、播放控制层按加载代际决定何时换目标。三者的存活时间不同，却都能影响"这条读句柄什么时候关"。

结果是一类反复出现的问题：播放播完不交还句柄；离开播放页在主线程关句柄；换目标时把新目标刚建好的源关掉；关闭与重连抢同一把锁。每次只修一处，另一处的时序又会冒出来。

另一处空白是重试该由谁做。会话层、回环代理、控制层都能重试，票面只说"作废后重连重发一次"，没写在哪一层。

## 决策

### 所有权

- **字节源只由回环条目持有与关闭。** 会话层提供"打开句柄"，不持有字节源；控制层只表达"当前还需要这个目标的源"，不直接关闭。
- **创建与关闭只在 IO 线程执行。** 界面线程只发命令并立即返回，不等待任何网络动作。
- **会话层按引用计数。** 读句柄与在途请求各占一个引用，句柄关闭与请求结束各自减一；只有归零才进入闲置计时。会话层不再自行判断"该不该关"。

### 归还时机

- 归还只认一个事实：**当前目标是否仍被读取**。以下情形是这一事实的举例，不是并列条件：播到结束、暂停在片尾、真正停止、换目标、切集接管成功、离开播放页且不再继续播放、退出。
- 离开播放页但仍在后台继续播放时，当前目标仍被读取，不归还。
- **判据看位置，不看索引。** 回环条目按位置复用，同一位置的不同列表项是同一条源；在它们之间切换不算换目标，不归还。
- 归还动作是"在发起那一刻摘走当时已就绪的源，再在后台关闭"。摘走之后才建好的源不属于这次归还，因此换目标不会误关新目标的源，也不会打断在途建源。
- 探测预置的句柄不走这条路径，由探测交接的覆盖、丢弃与关闭三条路径各自收尾；丢弃只在非调用线程执行，服务已关闭时由一次性关源线程收尾。
- 同一位置同一时刻至多一条就绪源；只有归还窗口内允许短暂两条（摘走之后、关闭完成之前该位置可能已建新源），不做额外阻塞。

### 重试分层

- 建立会话失败：不重试。会话建立总预算 5 秒只算一次。
- 打开共享或打开句柄遇传输类失败：作废该会话，重连一次，重发一次。
- 播放读的传输类失败与停滞（单次读等到上限仍未返回）一样：只作废该次读所在的会话，把原失败抛给调用方，会话层不重连，也不重发这次读。作废由回环层接住：给字节源打陈旧标记并断开连接。本轮加载失败后由控制层按加载看护重发，下一次请求在建源线程重建源后重取该段；播放中的停滞以结束本次会话收尾，不自动重发。会话层在这里重连的时间长于回环层 3 秒停滞判据，重连上来的句柄会被判陈旧，等于上下两层各重试一次，所以不在这一层重连。
- 认证失败、路径不存在、读取阶段的业务失败：不作废、不重试。

### 术语

- **重发**：控制层按加载看护以同一目标同一位置重新加载一次。
- **重取该段**：回环层下一次请求重建源后重新取该段数据。
- 两者不混用。

## 后果

- 关句柄只有一个入口，且只在 IO 线程，界面不会因为关句柄卡住。
- 换目标、片尾、切集、退出都走同一条归还判定，不再按状态枚举拼条件。
- 连续换片与连续切集不会按文件累积句柄。
- 代价：归还从"状态一变就关"变成"入队即摘走"，实现上需要条目提供摘走接口；主线程不再能立刻观察到句柄已释放，只保证已交出去。
- 代价：进程在后台关闭完成前被杀时，协议层关闭不会发出，交给系统断链。
